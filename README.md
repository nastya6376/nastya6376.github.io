# College App — лабораторные работы

Учебный проект: Flutter-приложение, автоматическая сборка APK в GitHub Releases
и четыре веб-страницы, которые читают и записывают данные в Supabase и Firebase.

Данные хранятся в собственных проектах автора: таблица Supabase `students_nastya`
и узел Firebase `students_nastya`. С общими проектами других лабораторных они
не пересекаются.

## Структура

```
.
├── index.html                  # главная страница (GitHub Pages)
├── lolipop.html                # отдельная страница сайта

├── firebase.html               # Firebase: select + insert
```

Сущность — студент: `name`, `specialty`, `grad_year`, плюс `id`.

## Что нужно сделать перед первым запуском

Проекты Supabase и Firebase создаются в аккаунтах автора. Пошаговая инструкция
лежит в файле [SETUP.md](SETUP.md): там SQL для таблицы, правила Firebase и
список значений, которые нужно вписать в конфиги.

Пока конфиги не заполнены, страницы открываются, но показывают предупреждение
«Конфигурация не заполнена» и не обращаются к базам.

## SQL для таблицы Supabase

```sql
create table if not exists public.students_nastya (
    id bigint generated by default as identity primary key,
    name text not null,
    specialty text not null,
    grad_year integer not null
);

-- Учебный режим: доступ без политик. Только для демонстрации!
alter table public.students_nastya disable row level security;

-- Публикация изменений для Realtime.
alter publication supabase_realtime add table public.students_nastya;
```

## Правила Firebase

```json
{
  "rules": {
    "students_nastya": {
      ".read": true,
      ".write": true
    }
  }
}
```

## Страницы

- `supabase.html` — читает таблицу и добавляет записи без перезагрузки;
- `supabase-realtime.html` — то же плюс подписка на изменения и журнал;
- `firebase.html` — то же для Realtime Database;
- `firebase-realtime.html` — подписка `on('value')` и журнал.

Тега `form` нет: кнопки вызывают JavaScript, страница не перезагружается.

## Локальная проверка

Страницы обращаются к базам по HTTPS, поэтому открывать файл двойным щелчком
нельзя. Проще проверить на опубликованном сайте:

- https://nastya6376.github.io/supabase.html
- https://nastya6376.github.io/supabase-realtime.html
- https://nastya6376.github.io/firebase.html
- https://nastya6376.github.io/firebase-realtime.html

Либо поднять локальный сервер из корня проекта:

```
python3 -m http.server 8000
```

и открыть `http://localhost:8000/supabase.html`.

## Сборка APK

Локально:

```
cd flutter_project
flutter build apk --release
```

Файл: `flutter_project/build/app/outputs/flutter-apk/app-release.apk`.

Автоматически: каждый push в `main` запускает workflow «Build Android APK».
Если сборка прошла, в разделе Releases появляется тег `build-N` с файлом
`college-app-nastya-N.apk`.

## Безопасность

- Публичные значения (Supabase URL, publishable key, Firebase Web config)
  хранятся в репозитории намеренно: они и так видны в исходниках страницы.
- `secret`/`service_role` ключи Supabase, пароль базы и приватные ключи
  в репозиторий не попадают.
- RLS выключен и правила Firebase открыты только ради учебной демонстрации
  с вымышленными данными.
