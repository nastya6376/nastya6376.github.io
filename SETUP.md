# Что нужно сделать в своих аккаунтах

Это короткая инструкция для автора проекта. Всё остальное — код, страницы,
сборка APK — уже готово. Здесь только то, что может сделать лишь владелец
аккаунтов: создать базы и взять из них публичные ключи.

Время: около 15 минут. Платить нигде не нужно, карта не требуется.

Что понадобится: почта, доступ к ней и браузер.

---

## Часть 1. Supabase

### 1.1. Регистрация

1. Откройте https://supabase.com
2. Нажмите **Start your project**.
3. Войдите через GitHub (кнопка **Continue with GitHub**) или зарегистрируйтесь
   по почте.
4. Подтвердите почту, если попросит.

Если аккаунт уже есть — сразу переходите к 1.2.

### 1.2. Создание проекта

1. Нажмите **New project**.
2. Заполните:
   - **Name**: `college`;
   - **Database Password**: нажмите **Generate a password** и сохраните его
     в надёжном месте. Он нужен только для администрирования базы, в код он
     не попадёт;
   - **Region**: ближайший, например `Central EU (Frankfurt)`.
3. Нажмите **Create new project** и подождите 1–2 минуты.

### 1.3. Создание таблицы

1. В левом меню откройте **SQL Editor**.
2. Нажмите **New query**.
3. Вставьте целиком:

```sql
create table if not exists public.students_nastya (
    id bigint generated by default as identity primary key,
    name text not null,
    specialty text not null,
    grad_year integer not null
);

alter table public.students_nastya disable row level security;

alter publication supabase_realtime add table public.students_nastya;
```

4. Нажмите **Run**.

Ожидаемый ответ: `Success. No rows returned`. Это нормально: команда создаёт
таблицу, а не возвращает строки.

5. Откройте **Table Editor** и выберите таблицу `students_nastya`.
   Должны быть видны колонки `id`, `name`, `specialty`, `grad_year`.

### 1.4. Ключи

1. В левом меню внизу откройте **Project Settings**.
2. Раздел **API Keys** (в некоторых версиях — **API**).
3. Скопируйте два значения:
   - **Project URL** — вида `https://abcdefghijklm.supabase.co`;
   - **publishable key** — начинается с `sb_publishable_...`
     (в старом интерфейсе он называется `anon`).

Эти два значения публичные, их можно отправлять в чат и держать в коде.

Важно: на этой же странице есть `secret` или `service_role` key. Его
**не отправляйте никому** — он даёт полный доступ к базе.

## Часть 2. Firebase

### 2.1. Проект

1. Откройте https://console.firebase.google.com
2. Нажмите **Create a project** (или **Add project**).
3. Введите имя, например `college-nastya`. Нажмите **Continue**.
4. Google Analytics можно выключить — для задания он не нужен.
5. Нажмите **Create project** и дождитесь **Continue**.

Проект должен остаться на бесплатном плане **Spark**. Карту не привязывайте,
кнопку **Upgrade** не нажимайте.

### 2.2. Realtime Database

1. В левом меню **Build** → **Realtime Database**.
2. Нажмите **Create Database**.
3. Выберите регион, например `europe-west1`. Нажмите **Next**.
4. Выберите **Start in test mode** и нажмите **Enable**.
5. Вверху вкладки **Data** будет адрес вида
   `https://college-nastya-default-rtdb.europe-west1.firebasedatabase.app`.
   Скопируйте его — он понадобится в 2.4.

### 2.3. Правила

1. На странице Realtime Database откройте вкладку **Rules**.
2. Замените содержимое на:

```json
{
  "rules": {
    "students_nastya": {
      ".read": true,
      ".write": true
    }
  }
}
```

3. Нажмите **Publish**.

### 2.4. Веб-приложение и конфигурация

1. Нажмите шестерёнку → **Project settings**.
2. Прокрутите до **Your apps** и нажмите значок **`</>`**.
3. Введите имя, например `college-web`. Галочку **Firebase Hosting** не ставьте.
4. Нажмите **Register app**.
5. Появится блок кода с объектом `firebaseConfig`. Скопируйте его целиком.
6. Нажмите **Continue to console**.

В конфиге обычно нет строки `databaseURL`. Это нормально: добавьте её вручную,
взяв адрес из шага 2.2.

Пример, как должно получиться (значения будут ваши):

```js
{
  apiKey: "...",
  authDomain: "college-nastya.firebaseapp.com",
  databaseURL: "https://college-nastya-default-rtdb.europe-west1.firebasedatabase.app",
  projectId: "college-nastya",
  storageBucket: "college-nastya.firebasestorage.app",
  messagingSenderId: "...",
  appId: "..."
}
```

## Часть 3. Что отправить

Три вещи, все публичные:

1. Supabase **Project URL**.
2. Supabase **publishable key**.
3. Firebase **firebaseConfig** (можно текстом, как скопировался, с добавленным
   `databaseURL`).

Можно просто вставить их в чат одним сообщением.

## Часть 4. Чего отправлять нельзя

- Supabase `secret` / `service_role` key;
- пароль базы Supabase;
- пароль от почты, GitHub, Google;
- файлы ключей и скриншоты с этими данными.

## Часть 5. Как проверим, что всё работает

1. Значения вписываются в `js/supabase-config.js` и `js/firebase-config.js`.
2. Изменения отправляются на GitHub, сайт обновляется через минуту.
3. На странице https://nastya6376.github.io/supabase.html появляется список
   записей и надпись «Загружено записей: 0» вместо предупреждения о конфигурации.
4. Добавляем студента — запись появляется в списке и в таблице Supabase.
5. На странице https://nastya6376.github.io/supabase-realtime.html появляется
   зелёный бейдж «подключено», а изменения из другой вкладки приходят сами.
6. То же самое проверяем для двух страниц Firebase.

Если на каком-то шаге появится ошибка — скопируйте текст ошибки целиком, он
подскажет, что именно не так.
